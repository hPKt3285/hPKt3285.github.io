Git over SSH on a restricted network

2026-11-04 · Kevin Lin

Port 22 is blocked on a lot of networks, including mine. The symptom is familiar: ssh -T git@github.com hangs and finally times out, even though the account and the key are both fine. GitHub publishes an SSH endpoint on port 443 for exactly this case, so the fix is a one-line change in the SSH config rather than anything on the account side.

The config

Add this to ~/.ssh/config:

Host github.com
  HostName ssh.github.com
  Port 443
  User git
  IdentityFile ~/.ssh/id_ed25519_hpkt3285
  IdentitiesOnly yes

The Host line stays github.com so that every existing remote keeps working unchanged; only the host name and port used for the connection are redirected. IdentitiesOnly stops the client from offering every key in the agent, which matters once there is more than one account on the same machine.

Checking it

ssh -T git@github.com
# Hi hPKt3285! You've successfully authenticated,
# but GitHub does not provide shell access.

git ls-remote git@github.com:hPKt3285/hPKt3285.git

The greeting is a success message, not an error. The second command proves that cloning and pushing will work over the same connection.

Signing commits with the same key

SSH keys can sign commits as well as authenticate them, which avoids keeping a separate GPG key around. The global settings look like this:

git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519_hpkt3285.pub
git config --global commit.gpgsign true

GitHub shows the commit as Verified as soon as the public key is registered as a signing key on the account. For local verification, add the key to an allowed_signers file and point Git at it:

echo "350152904+hPKt3285@users.noreply.github.com $(cat ~/.ssh/id_ed25519_hpkt3285.pub)" \
  >> ~/.ssh/allowed_signers
git config --global gpg.ssh.allowedSignersFile ~/.ssh/allowed_signers
git log --show-signature -1

Things that tripped me up

  • Windows OpenSSH refuses to use a private key that other users can read — the fix is to tighten the file ACL, not to copy the key somewhere else.
  • A key added for authentication is not automatically a signing key; GitHub needs it added a second time in the SSH and GPG keys page.
  • user.email should be the noreply address, otherwise the email in the commit does not match the account and the signature is verified but not attributed.
